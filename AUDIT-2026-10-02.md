## B. Umbrella feature proposals

- **F1 `locallab pipeline --var` and `--output-dir`**, with `continue_on_error`, `when:` conditions, and per-step `timeout`.
- **F2 `locallab doctor --tape`**: run one bundled sample tape through vcr → tokenauditor → linter → bridge → transcript-to-test and fail on envelope drift. This turns the "one shared tape" claim into a check.
- **F3 `locallab versions --check`**: compare installed versions against PyPI. Opt-in and network-only.
- **F4 `locallab init`**: scaffold a recipe, `tools.json` and a CI workflow.
- **F5 `locallab pipeline --junit/--json`** report for CI.
- **F6 More bundled recipes**: `bridge-and-audit`, `checkpoint-resume`, `breaker-guarded-record`.

## C. Per-tool feature proposals (unverified against code)

1. **agent-vcr**: `diff` command (already specced in FEATURESv1). Add secret redaction on record (`--redact` for API keys and auth headers). Add replay modes `strict`, `lenient` and `record-on-miss`. Add tape compaction and size limits.
2. **tokenauditor**: `--cost` with a vendored price table, per-tool-result attribution ("which tool call cost the most"), waste flag for repeated identical tool results, `--budget` exit code for CI.
3. **toolcall-linter**: SARIF output (specced), `--fix-suggestions` for enum and type errors, support for MCP `inputSchema` and JSON Schema `$ref`/`oneOf`, incremental `--watch`.
4. **transcript-to-test**: format auto-detect (specced), `--assert-mode` (exact, semantic, regex) for the final answer, a flaky-test warning if the tape has non-deterministic tool results, a unittest output option.
5. **agent-circuit-breaker**: soft-warn threshold (for example 80%) before the hard cap, per-model caps, `status` command and webhook-free local notification, a reset-day timezone setting, streaming-aware cost accounting for aborted responses.
6. **toolcall-cache**: `stats --watch` (specced), per-tool TTL overrides, cache invalidation by tag or server, a `--dry-run` that reports would-be hits, an integrity check against content hash.
7. **agent-checkpoint**: checkpoint rotation and pruning, a `list` and `diff` of checkpoints, checksum verification on resume, optional encryption at rest for secrets in state.
8. **transcript-bridge**: round-trip test mode (`a → b → a` with a loss report), `--strict` per-field allowlist, Gemini and Bedrock formats, batch directory conversion.
9. **mcp-openai-bridge**: HTTP/SSE transport support, schema sanitiser for OpenAI strict mode (`additionalProperties`, required fields), tool name collision handling across servers, a request timeout and retry policy.
10. **prompt-portability-linter**: portability score and `--suggest-fixes` (specced), rule packs per provider version, `--baseline` file to suppress known findings, a pre-commit autofix for trivial rewrites.

## D. Recommended order

2. A7, A8 and A9 next (pipeline correctness).
3. F2 (`doctor --tape`), because it backs the family's main claim.
4. Then the per-tool items, starting with agent-vcr redaction and circuit-breaker soft-warn.
